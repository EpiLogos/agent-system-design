# Part XVI — Development programme

## 61. Stage Q0 — Ratify module boundary

Deliver the specification, the canon/kernel/MEF/service/client distinction, shared semantic reference definitions, no-QL firewall requirements, and provider capability-negotiation contract.

---

## 62. Stage Q1 — Minimal deterministic kernel

Implement and test:

- Position and `4+2` structure;
- Face/direct-conjugate representation where canonically settled;
- `QLAddress` validation;
- `QLFormRef` registry;
- `LensRef` registry;
- provider capabilities;
- deterministic fixture provider;
- JSON schema fixtures.

This stage need not solve semantic refraction.

---

## 63. Stage Q2 — Full MEF registry and semantic contracts

Implement:

- all twelve lenses;
- sublens metadata;
- square/complement/Möbius relations as canonical registry data where settled;
- `QLTarget`;
- `QLReading`;
- `QLRelationReading`;
- `QLSynthesis`;
- provenance schema;
- refraction provider interface.

---

## 64. Stage Q3 — Base service operations

Implement:

```text
locate
refract
relate
synthesise
```

with structured unsupported/ambiguous results, deterministic versus semantic operation metadata, a CLI/JSON or equivalent reference transport, and fixtures.

---

## 65. Stage Q4 — AIKit and Factory adapters

Prove:

- existing Refs remain stable;
- readings return without target mutation;
- AIKit works in `NoQLProvider` mode;
- Factory works in `NoQLProvider` mode;
- optional readings can enter Claim/Evidence surfaces with provenance;
- lens use never silently changes trust/Action/Project ownership.

---

## 66. Stage Q5 — QL runtime integration

Connect the module to the Foundation Freeze runtime seam and experimental QL Direct Core.

Prove shared formal types where useful without forcing QL recurrence state into generic host contracts.

---

## 67. Stage Q6 — Deep QL parallel development

Develop on a separate track:

- conjugation;
- recursive depth;
- portable semantic events;
- typing witnesses/corpus;
- trace comparator;
- reference renderer;
- extension negotiation;
- research operators.

This track may progress while Pi/Pydantic/native adapters continue independently.

---

## 68. Stage Q7 — Evidence-led promotion

After experiments:

- compare operational parity;
- promote only stable operators/contracts;
- preserve research namespace for unresolved structures;
- update this module specification when evidence changes software semantics;
- do not revise QL canon merely because an implementation changed.
