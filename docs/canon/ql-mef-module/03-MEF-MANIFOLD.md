# Part VI — MEF manifold

## 22. MEF is first-class as a whole

MEF is not a menu of optional labels from which one application chooses two convenient names and forgets the rest.

All twelve lenses remain available as a canonical manifold.

A product may bind particular uses to particular lenses where real operational value has been demonstrated. Those bindings remain **role bindings**, not redefinitions of the lens.

---

## 23. Lens and sublens

Each lens carries a sixfold internal rotation.

The module should treat `LensRef + local position .0–.5` as distinct from the global raw QL address. A refraction can retain both which lens is active and which local sublens position is relevant without reducing the target to that coordinate.


Important software correspondences include investigative orientation, query formation, semantic affordance naming, latent versus articulated capability, prompts and questions, Skill descriptions, source handles, generated instructions, persistent artifacts/marks, and the relation between what is said and what remains open.

These are correspondences, not mandatory object mappings.

## 25. L0 — investigative orientation

L0 is especially natural for intelligent inquiry.

Its internal movement includes questions corresponding to:

```text
Why / presuppositional frame
What / definition
How / operation
Whom-Which-When / pattern
Where-Why-for / context
Why-so-Why-not / integrative return
```

A client may use L0 to orient an agent or source investigation without imposing six chronological prompts.

L0 can support question-addressable internal faculties in AIKit and Project Bootstrap while remaining an optional refraction rather than a compulsory dialogue script.

---

## 26. L0′ — archetypal-numerical

L0′ gives the number-grounded conjugate of L0.

The module should preserve the canonical lens and its numeric structure even where a software role has not yet earned operational parity. Numerical/harmonic operators remain an extension area unless their computational semantics are formally settled.

---

## 27. L5 / L5′ — articulation and realised word

L5 supplies the speech/code articulation movement from latent capacity through increasingly explicit expression. L5′ carries the conjugate realised Logos/work reading.

Software correspondences can include internal semantic formation, structured representation, generated language/code, persistent projection, and work returning as new context.

The module must not equate L5 with "final answer" or L5′ with "file write" universally.
